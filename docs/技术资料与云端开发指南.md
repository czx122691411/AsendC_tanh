### 相近算子参考：Sinh

- [官方算子列表](https://gitcode.com/cann/ops-math/blob/master/docs/zh/op_list.md)：已核对，包含 Sinh 和 Tanh，并列出 host、kernel、API 等实现情况。
- [Sinh 文档目录](https://gitcode.com/cann/ops-math/tree/master/math/sinh/docs)：可查算子规格和 aclnn 调用说明。
- [Sinh 工程入口](https://gitcode.com/cann/ops-math/tree/master/math/sinh)：保留供浏览器查看，本次工具未能读取目录源码。

Sinh 与 Tanh 都是一元逐元素算子，可以参考连续数据分核、UB 分块、CopyIn/Compute/CopyOut、队列同步、尾块和类型转换。数学计算必须调整：Sinh=(exp(x)-exp(-x))/2，Tanh 的分母则是 exp(x)+exp(-x)。不要只改算子名，也不要复制 Sinh 的数值范围、精度阈值或固定 Tiling 参数。上述是结构与数学层面的迁移判断，并非对某份 Sinh 题解源码的审查。官方库 master 的结构和接口也不保证与考试 CANN 9.0.0 模板一致。

## 2. 如何把题目下载到 GitCode Notebook

按官方部署指南，打开 Notebook 后进入 Terminal。以下命令在云端 Linux 终端运行，不是在本地 PowerShell 中运行。

```bash
mkdir -p ~/work/tanh_exam
cd ~/work/tanh_exam

wget -O TanhCustom.zip 'https://public-download.obs.cn-east-2.myhuaweicloud.com/%E5%BE%AE%E8%AE%A4%E8%AF%81/%E9%A2%98%E7%9B%AE/TanhCustom.zip'

# 先确认下载的是正常 ZIP，再查看包内目录
unzip -t TanhCustom.zip
unzip -l TanhCustom.zip
unzip TanhCustom.zip -d source

# 以实际解压结构为准，定位算子工程和测试工程
find source -name CMakePresets.json -o -name run.sh
```

如果没有 wget，可用 `curl -fL -o TanhCustom.zip '上面的完整下载地址'`。若下载失败或返回网页，可先在本机从考试页面下载官方 ZIP，然后通过 Notebook 文件面板上传，再在终端解压。不要对 ZIP 执行 tar 解压。

在 Notebook 单元格中运行多行命令时用 `%%bash`；工作目录跨单元格切换用 `%cd`，避免以为 `!cd` 会改变后续单元格目录。构建、安装和测试建议统一使用 Terminal。

结论：技术上可行。官方手册明确支持 Ascend C 开发，提供 A2/A3 NPU 和 CANN 9.0.0 正式版环境。需检查你实际实例是否满足题目要求；本次没有登录或运行你的云实例。

建议优先选择与官方 Notebook 同型号的单卡 NPU；不能确认时先考虑 A2，并核对模板的目标芯片配置。CPU 仿真实例可辅助验证逻辑，但不能代替真实 NPU 上的 aclnn 验证。

### 3.1 准备工程与环境

CANNLab 中把工程放在 `/mnt/workspace`：关机后该目录保留，删除实例则不保留。官方手册记载初始 100 卡时；当前账号可用额度以控制台为准。运行状态会消耗卡时，关闭浏览器不能视为关机。

```bash
mkdir -p /mnt/workspace/tanh_exam
cd /mnt/workspace/tanh_exam
# 在此运行第 2 节的 wget/unzip 命令

npu-smi info
uname -m
printenv | grep -E 'ASCEND|CANN'

# 官方手册所列常见路径，先检查实际实例
ls -l /home/developer/Ascend/ascend-toolkit/latest
cat /home/developer/Ascend/ascend-toolkit/latest/opp/version.info
```

选择 CANN 9.0.0 正式版本，避免误用 master 或 beta 镜像。按实际安装位置加载环境，例如存在相应文件时：

```bash
source /home/developer/Ascend/ascend-toolkit/set_env.sh
```

将算子工程 `CMakePresets.json` 中 `ASCEND_CANN_PACKAGE_PATH` 改为实际 Toolkit 根目录。例如该目录经检查对应 9.0.0 时，可填写 `/home/developer/Ascend/ascend-toolkit/latest`。不要照抄考试截图中的 `/usr/local/Ascend/...` 路径。

### 3.2 构建与原题验证

1. 补齐原工程已有文件，保留 AclNNInvocation 不变。
2. 在包含 build.sh 的算子工程目录运行 `bash build.sh`。
3. 进入 build_out，确认实际生成的 `.run` 文件名，再执行对应安装包；不要照抄其他架构的包名。
4. 按安装日志加载自定义算子的库路径或环境脚本（如有要求）。
5. 进入原始 AclNNInvocation 目录运行 `bash run.sh`，确认精度通过。

如更换 NPU 型号，应重新按目标芯片构建；不要跨型号直接复用 kernel 二进制。缺头文件或库时先检查 Toolkit、所需组件及环境变量；不要通过修改原题测试文件绕过问题。

## 4. 用户提供的 Sinh 认证参考实现

[Kkwavectl/ascendc_GPU README](https://github.com/Kkwavectl/ascendc_GPU/blob/main/README.md)，2026-10-16 已阅读内嵌的 host、Tiling 与 kernel 代码。这是第三方参考，不是本题官方工程。

可借鉴双缓冲队列和 CopyIn/Compute/CopyOut。代码固定 8 核、tileNum=8、双缓冲；按整数除法分块，没有尾块处理，也没有按 UB 容量选择 tile。临时张量使用输入类型，因此 FP16 输入时中间计算也是 FP16。迁移时需重新处理非整除长度、搬运对齐、UB 容量和数值精度。

Tanh 可沿用指数差作为分子，并计算指数和作为分母；大幅值时仍需避免指数溢出。该 README 的 Sinh 题面明确禁止 Sinh 高阶 API。我们已读取的本地 Tanh 题面未见相同条款，但建议先用基础指令实现，并核对原始模板注释。
