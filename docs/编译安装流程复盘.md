## 总览

```
源码 (.cpp/.h)                    阶段 1-2: 编译                阶段 3: 打包           阶段 4: 安装              运行时
─────────────                   ─────────────               ─────────────         ─────────────           ──────
op_host/tanh_custom.cpp  ──g++──► 3 个 host 动态库 ─┐

```

## 阶段 0：入口（`bash build.sh`）

`build.sh` 只做三件事：

1. 确认 `ASCEND_HOME_PATH`（否则报 `please set env`；先 `source ~/Ascend/cann-9.0.0/set_env.sh`）。
2. `cmake -S . -B build_out --preset=default`——读 `CMakePresets.json`，锁定：
   - `ASCEND_COMPUTE_UNIT=ascend910b`（kernel 编译目标）
   - `ASCEND_CANN_PACKAGE_PATH=/home/developer/Ascend/cann-9.0.0`
   - `vendor_name=customize`（决定安装目录名）
3. 依次构建 `binary` 和 `package` 两个 target。

## 阶段 1：host 侧编译（g++，aarch64）

同一个源文件 `op_host/tanh_custom.cpp` 被编译 **3 次**——不是重复，是它同时扮演三个角色：

| 产物 | 源 | 功能 | 被谁调用 |
| --- | --- | --- | --- |
| `libcust_opmaster_rt2.0.so`（tiling 库） | `TilingFunc` | 读输入 shape → 算 `totalLength/tileNum`/8 核切分 → 写 tiling 数据 | 推理阶段，host 上 |
| `libcust_opsproto_rt2.0.so`（op_proto 库） | `InferShape`/`InferDataType` + `OP_ADD` | 形状/类型推导规则（x→y，fp16→fp16），向算子仓库注册 `TanhCustom` | 图阶段，host 上 |
| `libcust_opapi.so`（aclnn API 库） | 自动生成的 `autogen/aclnn_tanh_custom.cpp` | 提供 `aclnnTanhCustom(...)` 入口：申请 workspace、起 kernel、管理 stream | 调用方（AclNNInvocation） |

另有 `libcust_tf_parsers.so`（framework/tf_plugin），供 TensorFlow 框架对接，aclnn 链路用不到。

## 阶段 2：kernel 侧编译（BiSheng/CCE，最关键）

```
[ascend910b] Generating TanhCustom_9d11ee3633f584c6342b586860ca562b ...
```

`op_kernel/tanh_custom.cpp`（含 `AscendC::Tanh` 调用）**不经过 host g++**，而由 Ascend C 编译器生成 **NPU AI Core 二进制** `TanhCustom_<hash>.o`：

- 文件名中的 hash 是 kernel 签名摘要，运行时据此匹配二进制。
- 这就是「CPU 域孪生调试」与真机的分界：同一份源码，CPU 域用 g++ 编成可执行 harness（`experiments/tanh_numeric/`），真机用 CCE 编成 `.o`。

## 阶段 3：打包（CPack → `.run`）

`package` target 把上述产物按固定目录结构组装成自解压脚本 `custom_opp_ubuntu_aarch64.run`：

```
packages/vendors/customize/
├── op_impl/ai_core/tbe/kernel/ascend910b/tanh_custom/TanhCustom_<hash>.o   # NPU 二进制
├── op_impl/ai_core/tbe/op_tiling/liboptiling.so                            # tiling 库
├── op_api/lib/libcust_opapi.so                                             # aclnn 入口
├── op_proto/lib/linux/aarch64/libcust_opsproto_rt2.0.so                    # 形状/类型推导
└── uninstall.sh / upgrade.sh
```

附 SHA256 校验和。

## 阶段 4：安装（自解压 → CANN vendors 目录）

```bash
./build_out/custom_opp_ubuntu_aarch64.run
```

- 校验 SHA256 → 解压到 `~/Ascend/cann-9.0.0/opp/vendors/customize/`。
- 该位置不是任意的：CANN 运行时**自动扫描 `opp/vendors/`** 下的第三方算子包（`customize` 即 preset 里的 `vendor_name`），这就是「装完即被发现」的机制。
- 本次安装日志有一条权限 WARNING（对 CANN 根目录无写权限时走兜底创建，实际写入成功）。若后续报「找不到算子」，第一个排查点就是 `ASCEND_CUSTOM_OPP_PATH`。
- 此版本安装包**不生成** `set_env.bash`，运行前需手动：

```bash
export LD_LIBRARY_PATH=/home/developer/Ascend/cann-9.0.0/opp/vendors/customize/op_api/lib/:$LD_LIBRARY_PATH
```

## 串回真机调用链

`AclNNInvocation` 跑起来后的完整链路：

```
AclNNInvocation 二进制
  → libcust_opapi.so 的 aclnnTanhCustom()         （阶段 1 产物）
  → 调 libcust_opmaster_rt2.0.so 算 tiling        （阶段 1 产物，host 上执行）
  → tiling 数据 + TanhCustom_*.o 下发到 NPU 910B3 （阶段 2 产物，device 上执行）
  → 8 个 AI Core 并行跑 AscendC::Tanh
```

编译器的三份「翻译」（proto 注册 / tiling 决策 / kernel 计算）各司其职，缺一环节调用链即断；排查「找不到算子」类问题时按此链路逐级定位。
